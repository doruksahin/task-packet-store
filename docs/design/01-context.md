Surveyed on 2026-09-04 across three repositories.

## The packet

Path: `adc-vault/10 Tasks/Packets/<TICKET>/`. Shape defined by
`adc-vault/00 System/Work OS/Task Packet Blueprint/blueprint.md` (schema version 2).

```text
ATT-5215/
  00 Packet.md            generated by work-os
  task.md                 human root note
  jira/                   generated by jira-markdown-exporter, profile work-os-v1
    00 Issue.md  10 Comments.md  20 Attachments.md  90 Sync.md  attachments/
  stages/                 human scaffolds, one folder per workflow stage
    10-recon/ 20-ac-walkthrough/ 30-implementation/ 30-delivery/ 40-code-review/
    50-verification/ 70-handoff/ 80-decisions/ 90-evidence/
  sessions/               session-marking writes sessions/<provider>/<id>.md
```

The vault `AGENTS.md` names the packet "the canonical execution memory". Stage folders hold only a
`README.md` launcher and a few human templates. No tool writes into them.

## jira-markdown-exporter

Repository `doruksahin/jira-markdown-exporter`, npm `@doruksahin/jira-markdown-exporter@0.5.0`.
A read-only, one-shot CLI. It writes `<output>/<KEY>/<ownedDirectory>/` and a JSON receipt. The vault
pins it in `.obsidian/plugins/work-os/package.json`. The vault workflow `jira-export-smoke.yml` runs
it into a temporary directory and publishes into a disposable checkout. Nothing commits.

Standards visible in this repository and reused here: exact-version pins, Release Please manifest
mode, Conventional Commits, SHA-pinned actions, npm trusted publishing, credential-free config,
credentials from named env vars only, JSON stdout with exit codes 0/1/2, a self-contained `--help`,
closed JSON schemas, a package-boundary test.

## AC-visual-walkthrough

Repository `doruksahin/AC-visual-walkthrough` with upstream `AdCreative-ai/AC-visual-walkthrough`.

- `packages/packet-store/` fetches one frozen packet from an `fs` root or an S3-compatible bucket.
  Frozen semantics: validated paths, read-only files, no merge, cleanup on failure, a digest.
  ADR-0015 records the decision. The workflow `walkthrough-lab.yml` fetches from the Cloudflare R2
  bucket `ac-walkthrough-packets`.
- `runtime/scripts/src/walkthrough-store/` persists run output with `begin`, `checkpoint`, `seal`
  into `AdCreative-ai/ac-walkthrough-artifacts` through Git and LFS. ADR-01M1GBDK records it.
- `packages/jira-publisher/` attaches the HTML report to the Jira issue and posts a comment.
- The workflow's `observe_phases` shell function already watches `storage-state.json` and reacts to
  the reasons `initialized`, `evidence-captured`, `capture-finished`, `report-authored`,
  `report-rendered`, and `failure-boundary`.

## Recon plugin

Repository `doruksahin/recon-plugin`. Writes to `$RECON_ROOT/<TICKET>/{triage,discovery,route,repro}/`
and delivers a dossier HTML and a zip to Jira as attachments.

## The three gaps

1. Nothing uploads a packet to R2. A grep of both repositories finds no uploader. Doruk uploads by
   hand.
2. No tool output lands in a stage folder. The walkthrough writes to its own artifacts repository.
   Recon writes to `$RECON_ROOT`. Both reach the packet only as Jira attachments that the exporter
   downloads again into `jira/attachments/`.
3. `packetSha256` hashes the whole packet, including `stages/` and `sessions/`. A writable packet
   breaks the identity on every run.
